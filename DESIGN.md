## Intent & Direction

- Current direction: **decided 2026-08-08** — the desktop web UI runs the unified system from `docs/design/2026-08-08-unified-system/` (approved section mockups + `IMPLEMENTATION.md` beslut 1–3), **plus the signature pass** (same day, this doc's own section below) laid on top of it without reopening any of its decisions.

## Aesthetic Character (interpretation)

Quiet, paper-forward operational UI for volunteer boards: warm off-white workspace, raised white panels, warm near-black ink. Typography does epistemic work with weight, not serifs — display sans asserts (answers, titles, quotes), sans explains (chrome, labels), mono measures (states, dates, page numbers). Colour is reserved for meaning (grounded / refusal / searching / machine failure), not decoration. Density is tool-like without dashboard chrome; the document PDF is the one pure-white surface. **Since the signature pass:** the same quiet system now has exactly one loud moment built into it on purpose — see below — rather than being uniformly quiet everywhere, which is what read as "no identity" before.

## Signature & Composition

*Read this before adding a new hero, empty state, or first-run screen — it is the
rule the rest of the app should follow, not a one-off.*

**The problem this pass fixed:** the unified system was internally consistent but
had no signature — nothing was bigger, bolder, or more alive than anything else,
including `TraffMark`, which is a genuinely distinctive idea (a ring whose gap is
literally "the distance between a question and its proof," §02) that had never
shipped bigger than 22px in a sidebar corner. Fresh-pilot screens (mostly empty)
made this worse: five workspaces in a row showed the identical generic dashed-box
+ Lucide-icon empty state.

**The fix has two parts, and they're meant to be reused together:**

### 1. The ring, animated — the product's one signature

`TraffMark.jsx` now carries real motion for `variant="status"`, driven entirely by
CSS so no call site has to orchestrate it:

| State | Look | Rule |
|---|---|---|
| `vila` | Dim ink ring, no core, static | Nothing established yet — the resting state |
| `soker` | Full `--sokljus` blue ring **+** a white travelling highlight (`.traff-mark-seek`, spins on `--mark-ring`, a CSS custom property set inline per instance) | The solid ring alone still reads correctly with `prefers-reduced-motion` — meaning is never carried by motion alone (§01) |
| `belagt` | `--belagt` green ring, core plays a one-time arrival (`traff-core-in`, 0.42s, scale+opacity) **exactly when it mounts** | Never a generic fade replayed on every render — it plays once, on the actual event, because a core appearing *is* the event |

**The one rule that must never be broken while extending this:** the ring's own
gap stays empty — no tint, gradient, or glow placed *behind the ring shape
itself* (§02, enforced by a prior identity decision documented in `Login.css`,
where an earlier glow/halo treatment was tried and explicitly reverted). The
mark can sit on a dark **ground** (see below) — that's the panel's background,
not a plate behind the mark — but nothing may sit between the ring and the gap.

Used at hero scale (64–84px) in: the login screen, `Fråga dokumenten`'s empty
state, and as the shared glyph in every `EmptyState` (`vila` for "nothing yet",
`belagt` for tone `"ok"` / "all handled") — one motif, not six different Lucide
icons per section.

### 2. The split panel — for first-moment screens only

A bigger version of the old centered card still read as the same layout. The
actual fix was compositional: an **ink ground** (thesis + the mark, left-aligned,
mark rendered in `--papper` not `--foreground`) beside a **paper ground** (the
actual functional work — a form, a suggestion list). Same shape both places,
different content:

- `Login.jsx`/`Login.css` — `.login-brand` (ink) / `.login-form-col` (paper), grid `minmax(380px,40%) 1fr`, stacks under 768px.
- `App.jsx`/`App.css`, `Fråga dokumenten`'s empty state — `.chat-empty-brand` (ink) / `.chat-empty-body` (paper), grid `1fr 1.35fr`, stacks under 768px.

**When to use it:** the *split panel specifically* — ink beside paper, 40/60 —
stays on screens where someone arrives with literally nothing yet: a login, an
empty conversation. That is a statement about **that composition**, not a budget
for boldness overall.

**Superseded 2026-08-08 (Simon, explicitly): "spend the boldness once" is dead.**
It used to read "spend the boldness once, on arrival; everywhere else stays
disciplined," and every pass that touched a working screen dutifully obeyed it
and shipped changes the product's owner could not see. Several rounds of that —
a masthead here, a thin bar row there, half of them gated behind counts an empty
association does not have — is what "I can't even tell if you changed anything"
was actually describing. The rule was the cause, not the passes.

The working screens now open on a **full-bleed ink masthead band** (`.page-header`
in `App.css`; Bevakningar, Uppgifter, Fakturor, Inkommande and Dokument all opt
in by carrying the class). It is not login's split panel — it runs horizontally
across the top and hands the page below it back to the quiet paper system, which
is untouched. Two constraints it must keep:

- **It reads at zero data.** An empty association sees the same band as a full
  one. Any new compositional element that renders `null` under a zero count is
  invisible to the person who most needs to see the screen has a design.
- **One bold move per screen, at the top.** The band is the assertion; the rows,
  filters and cards under it stay disciplined. Boldness everywhere is the same
  flatness as boldness nowhere.

### 2b. The plate — one frame, five instruments (2026-08-08, system pass)

The band above was right and its *execution* was five separate implementations.
Measured live before this pass, across Dokument / Bevakningar / Uppgifter /
Inkommande / Fakturor:

| | band height | content left edge |
|---|---|---|
| before | 149 / 290 / 292 / 149 / 277 px | 288 / 366 / 366 / 288 / 288 px |
| after | 268 px on all five | 288 px on all five |

Changing tab resized the largest element on screen by up to 143px, and on two
screens the title and the rows it headed stood on different left edges. That
misalignment is the thing a reader registers as amateurish without being able to
name it — it is what "lekstuga på alla sidor" was pointing at.

**The rules now, enforced structurally rather than per screen:**

- `.page-header` is a **CSS grid** with named areas — `title` / `actions` /
  `instrument` — at a **fixed `--band-h`**. Flex was why each screen needed its
  own patch (`order: 1` here, `margin-left: auto` there, a nested second flex row
  on Fakturor to get the same arrangement a third way). The grid states the
  arrangement once and no screen has to be told to get out of another's way.
- Markup contract: every band emits `.page-header-text`, `.page-header-actions`
  and `.page-header-instrument`. A workspace gets the faceplate hairline and the
  shared caption style by **being** a workspace, not by remembering to ask.
- The instrument is bottom-aligned, so all five readings share a baseline.
- **Every screen has an instrument**, because the height is fixed and an empty
  plate is worse than no plate. Fakturor: öppet belopp + four case counts.
  Bevakningar: the twelve-month horizon + three state counts. Uppgifter: three
  numerals. Dokument: sökbara sidor (pages, not files — a citation lands on a
  page). Inkommande: att avgöra + väntar svar + inkommet.
- **Mono measures, on every screen.** Uppgifter's numerals were Poppins while
  Fakturor's and Bevakningar's were mono — the same widget in two typefaces, one
  tab apart.
- A reading appears **once**. Moving an instrument into the band means deleting
  the paper copy below it (`.watches-counts`, `.tasks-counts`, Dokument's
  register line, Inkommande's tab counts) — otherwise the same number is on
  screen twice and neither is authoritative.
- Under `max-height: 780px` the plate gives up its fixed height and drops the
  instrument, still identically on every screen.

### 2c. Geometry — three radii, three control heights, one spacing ramp

The audit that prompted this found the stylesheets carrying **seven radii**
(plus raw 9/10/11/12/14/16/20px), **thirteen control heights** (20→44px) and
**nineteen gap values**, against a nine-step spacing scale that had been declared
in `theme.css` and then used essentially nowhere. A scale nobody spends is a
comment, not a system.

- **Radius: `--r-sm` 8px operated / `--r-md` 12px held / `--r-lg` 18px sheets.**
  The old names (`--radius-2xl` etc.) are aliases onto these, so 100+ existing
  declarations inherit the correction untouched. Controls came **down from
  18px** — an 18px corner on a 32px button is 56% of its own height, which is a
  lozenge, and a screen of lozenges is the toy look.
- **Height: `--h-sm` 28 / `--h-md` 36 / `--h-lg` 44**, chosen by role. `--h-md`
  is the default for every button, input, select and filter.
- **`<select>` is styled at the element level**, not via `.ui-select`. Fakturor's
  four filters were bare selects that got a border from a stylesheet but never
  `appearance: none`, so the whole filter row was drawn by the OS — four platform
  widgets in a row inside the product's own fields. Watch for the
  `background:` **shorthand** in component sheets: it resets `background-image`
  and silently erases the chevron. Use `background-color`.
- **The sidebar is paper (`#FBFAF9`), not `#FFFFFF`.** The app was running three
  grounds at once and the coldest was the one permanently on screen. `#FFFFFF`
  stays reserved for a document.

### 3. Masthead weight — every workspace's name is the one assertion

`.page-title` and `.chat-title` are Poppins 600 at 34px (`2.125rem`,
`letter-spacing: -0.02em`) — up from an inconsistent 400-weight 30px that in
Uppgifter's case wasn't applied at all (`<h2>Uppgifter</h2>` had no class and
rendered at the browser's bare `h2` size). All five PRODUCT_WORKSPACES titles —
Dokument, Fakturor, Bevakningar, Uppgifter, Fråga dokumenten — now match each
other and match the weight `Fråga dokumenten` always had. Inkommande is the one
exception, structurally: it's a two-tab switcher ("Inkommande / Anslutningar"),
not a single workspace title, so `.page-title` doesn't apply there by design.

## Typography

Vendored woff2 under `brfv2-mockup/src/assets/fonts/` (and mirrored on mobile). No Google Fonts fetch (`font-src 'self'`).

| Role | Family | Job |
|---|---|---|
| Display / assertion | Poppins 500/600, tracking −0.015…−0.02em | Page titles, brand name, `.ui-section-title`, chat titles, empty-state headlines |
| UI / explanation | Inter 400/500/600 (+ italic) | Body, labels, chrome, `.citat`, answer body (17px) |
| Measurement | JetBrains Mono 400–700 | States, dates, page counts, eyebrows, `.matt`, `.kbd` |

Desktop scale (`theme.css`): `--text-xs` 12 → `--text-sm` 14 → `--text-base`/`--text-md` 15 → `--text-lg` 17 → `--text-xl` 24 → `--text-2xl` 30. Body line-height **1.6**. The serif assertion floor is gone — assertion is carried by Poppins 600 + tight tracking at the same sizes. `--font-serif` survives only as a deprecated alias of `--font-sans`; Instrument Serif woff2 is deleted from `assets/fonts/`.

**Masthead size, above the named scale (signature pass):** `.page-title` and `.chat-title` are `2.125rem`/34px at weight 600 — one step above `--text-2xl`, not on the named scale, because it's deliberately used in exactly one place per screen (see "Signature & Composition"). The login brand name is bigger again, `2.75rem`/44px, because it's the one screen that opens on nothing else.

**Sub-12px contrast rule (beslut, 2026-08-08):** mono/meta text under 12px uses `--ink-muted` (`#605A57`), never `--ink-subtle`, to hold WCAG AA on the paper ground.

Mobile PWA body is **16px** (`--t-body: 1rem`); the PWA answer layer is still Instrument Serif at 22px — deliberate divergence until the mobile pass.

## Spacing, Sizing & Layout

- Named spacing scale on desktop since 2026-08-08: **`--s1…--s14`** (4px base, up to 56px). Mobile PWA has explicit `--s1…--s10`.
- Shell: sidebar **260px** with grouped nav (`Fråga & arkiv` / `Arbete` / `Post & ekonomi` mono section labels), main content padding **28×32×40**, chat column max **780px**.
- **Wide-window register cap (signature pass):** Inkommande, Fakturor, Bevakningar and Uppgifter — the four PRODUCT_WORKSPACES pages that are tables/lists, not canvases — cap at **1600px**, centered (`.tab-content--wide` in `App.css`, applied conditionally in `App.jsx`'s workspace map). Below ~1920px total window width this is invisible (natural content is narrower than the cap); above it, it stops a register from stretching into dead gutter on an ultrawide monitor. Hemsidan is explicitly excluded — it owns a canvas.
- Controls: **`--h-control` 36px** default height (sm **30px**), **`--r-control` 10px** radius, **`--r-card` 14px** card radius; badges/counts **20px**.
- Page pattern: `.page-header` + Poppins `.page-title` (now 34px/600, see Typography) + muted subcopy (`max-width` ~72ch).
- Breakpoints: **locked to 1200 / 1024 / 768 / 560** (beslut 2) — `design-lock.test.js` fails on any other `@media` width under `src/`. The split-panel pattern's own stack point reuses **768px**, not a new value.
- Density: operational lists/tables; empty states are one shared pattern (`.ui-empty`, see Components) — now built around the `TraffMark` glyph instead of a per-section icon.

## Surfaces: Radius, Borders, Shadows

| Token | Approx | Use |
|---|---|---|
| `--r-control` | 10px | Controls (buttons, inputs) — canonical since 2026-08-08 |
| `--r-card` | 14px | Cards / panels, incl. the invoice ledger and empty-state card |
| `--radius-sm` … `--radius-xl` | 6–14px | Small chrome (legacy scale, still in use) |
| `--radius-2xl` / `--radius-3xl` | 18px / 24px | Legacy control/card radii — new work uses `--r-control` / `--r-card`; the split panels (`.login-panel`, `.chat-empty-state`) use `--radius-3xl` |
| `--radius-block` | 12px | Multi-line content (textarea, answer sheet, tall prompts) |
| `--radius-pill` | 999px | Badges, segmented tabs |

Borders: 1px warm greys. Shadows: soft ink-tinted `--shadow-xs` → `--shadow-lg` (popover / modal) plus `--shadow-sheet`, the workspace surface at rest. Elevation model (app-frame pass, 2026-08-08): paper ground → white sidebar chrome (faint seam shadow) → **the sheet** — a workspace is one white surface (`--r-card`, `--shadow-sheet`, 22–24px internal padding) floating on the paper; page chrome (masthead, instrument rows) sits *on the paper above it* (`.page-header.is-on-paper`) → modal over `rgb(55 50 47 / 0.38)` scrim. Fill-height workspaces (chat, Inkommande) stretch the sheet and scroll internally; the PDF reader and Hemsidan canvas own their area and are exempt (`.tab-content:has(...)` resets). Declared once: a surface takes a border *or* a shadow's edge, never a heavy stacked pair. Dividers via 1px `--border` more than heavy cards everywhere; cards used for interactive/work surfaces (`.ui-card`, `.glass-panel`, chat empty, tables).

## Motion & Interaction

- Short transitions: **0.12–0.15s** ease on hover colours; sidebar **0.24s**; skeletons pulse **1.8s**; spinner **1s** linear.
- **TraffMark motion (signature pass):** `soker` spins a travelling highlight at **1s** linear; `belagt`'s core arrives once over **0.42s** (`cubic-bezier(.34,1.4,.4,1)`, a slight overshoot) exactly on mount, never replayed. Both governed by the existing global `prefers-reduced-motion` rule below — no separate opt-out was added, meaning is never carried by motion alone.
- Focus: **one ring** — 2px `--ring` (Handling blue) with 2px offset on every control. List rows draw it inset (`box-shadow: inset 0 0 0 2px`) plus a `--handling-soft` tint so card rounding never clips it. The 3px glow token is deleted; design-lock fails on its return. Sidebar nav keeps a dense 2px box-shadow ring (no offset) by deliberation.
- Keyboard flow (2026-08-08): `/` focuses the view's own filter (`useSlashFocus`), ↑/↓ move the mark in the Inkommande thread list and Fakturor register, Enter opens the marked item, Esc steps back / empties the filter.
- Hover: surface shifts (`--surface-2` / `--muted-hover`), not hue flips on primary (primary darkens ink).
- `prefers-reduced-motion: reduce` collapses animation/transition durations globally (`theme.css`) — this is what makes the ring's motion safe to add without a second accessibility mechanism.
- Mobile PWA names motion tokens (`--ease`, `--d-push` 180ms, `--d-sheet` 240ms).

## Visual Rhythm & Composition

- **Shell:** optional scope strip → white sidebar (brand lockup over a seam, grouped nav under mono section labels, selected item = muted fill + 2px ink leading tick, BRF card + user footer) → paper main canvas.
- **First-moment split (signature pass):** login and `Fråga dokumenten`'s empty state open on an ink ground carrying the mark and the thesis, beside a paper ground carrying the actual work. See "Signature & Composition" for the rule on where this does and doesn't apply — it is not the shell's default, it's reserved for arrival.
- **Workspace opener (app-frame, 2026-08-08):** chrome on the paper — Poppins masthead + short muted intro, then Fakturor's **instrument row** (11px mono uppercase labels, 22px tabular mono figures, hairline separators, the non-zero count underlined in ink) — then the sheet. Work on the sheet: docked controls, the register, case panels. Evidence: `docs/design/2026-08-08-app-frame/shots/`.
- **Ask loop:** question in sans with mono “FRÅGA”-style label; answer as bordered sheet in Inter 17px; citations and PDF reader as provenance, not chat bubbles. Once a conversation has messages the split panel is gone and this quieter rhythm takes over — the signature is an arrival moment, not a permanent frame.
- Hierarchy: type role first, then weight/spacing, then meaning colour. Colour is scarce on purpose — the signature pass spent its boldness on scale and motion, not new hues.
- Alignment: left-led reading columns; tables as “registers” with mono column headers on a half-step rail (`--surface-1`), 44px+ rows, hover `--surface-2`, tabular numeric columns (invoice ledger carries the register language: mono headers, `--r-card` wrap at `--shadow-sheet`).

## Distinctive Choices

1. **Colour locked to epistemic meaning** — green = verified passage; amber = no proof; blue ring = searching; red = machine break only; primary CTA is ink.
2. **Three type cuts, three jobs** — display sans asserts, sans explains, mono measures; never mixed for the wrong job. (Until 2026-08-08 the assertion cut was Instrument Serif; it is now Poppins by deliberate decision.)
3. **Paper desktop vs dark-shell phone** — same identity, inverted ground for long reading sessions vs phone “mörkt skal, lysande papper”.
4. **Träff mark as status language** — empty until belagt; brand mark never wears state colour.
5. **Document is the only pure white** on desktop (PDF); workspace is warm paper.
6. **Overdue is mono weight/edge, not red** (`.matt--overdue`, `.rule-overdue`).
7. **Hemsidan canvas is a second design system** so editors see what members see.
8. **Durability by test, not convention** — one button primitive, four breakpoints and one focus ring are enforced by `design-lock.test.js`, not by reviewer memory.
9. **The ring is the signature, and it's earned, not decorative** (2026-08-08, signature pass) — `vila`→`soker`→`belagt` is the product's own epistemic claim ("empty until proven") turned into the one moment the app is visually remembered by, reused at hero scale in exactly the places that claim is literally true (login, an unanswered question, an empty section) and nowhere else.

## Inconsistencies & Competing Directions

Resolved 2026-08-08 (unified-system pass): dual button CSS (`.primary-action-btn*` deleted, design-locked), breakpoint sprawl (four locked widths), the 3px focus glow (one ring, token deleted), serif/sans split on desktop (sans-first), ad-hoc empty states (one `EmptyState` pattern).

Resolved 2026-08-08 (signature pass, later same day): TraffMark shipping invisibly at 22px with no motion (now animated, used at hero scale); six different Lucide icons across empty states (now one ring glyph, `EmptyState.jsx`'s `icon` prop removed entirely); `.page-title` inconsistent across workspaces — Uppgifter had no class at all, the other three were 400-weight 30px against `Fråga dokumenten`'s always-600 title (all five now match); login and the chat empty state read as "a card in a void" (now the split-panel pattern); demo credentials hidden behind `import.meta.env.DEV` in a pilot build whose own premise (`DEMO.md`) is running without a developer present (hint now unconditional).

Resolved 2026-08-08 (consistency pass, evening, found by live-screenshotting the four working screens the signature pass didn't touch — `brfv2-mockup/src/visual-{bevakningar,uppgifter,inkommande}.jsx`, new harnesses mounting the real components rather than a hand-copied shell): Inkommande's tab switcher carried no masthead weight at all and jumped straight into "Ingen brevlåda är ansluten" with no framing sentence — every other workspace opens with one (`Integrations.jsx`/`.css`, tab type now matches `.page-title` at 2.125rem, added `.integrations-header-text` + subcopy). Uppgifter's instrument row (`.tasks-counts dd`) rendered its numbers at `--text-lg` (17px), a full step under the identical pattern on Fakturor's `.invoices-counts dd` (1.5rem) — same shape, quieter for no reason tied to its own content (now matches). Bevakningar had no instrument row at all, only a plain mono sentence (`.watches-summary`) — it now gets the same four-figure row (`.watches-counts`: Bevakas / Förslag / Försenat / Odaterat) Fakturor and Uppgifter both have, with the plain sentence demoted to a caption (`.watches-today`) above it.

Remaining:

- **Signature applied to first-moment screens only, by deliberate choice.** Populated/working screens — a filled Fakturor register, Bevakningar/Uppgifter with real rows, an open document — still run the original quiet system untouched. Whether that boundary is permanent or the next section to reconsider is an open question, not yet decided (see Open Questions).
- **Bevakningar and Uppgifter's own empty states get the ring glyph but not the split panel** — only the login and `Fråga dokumenten` got the full two-zone composition. Consistent with the rule ("split panel means true first-arrival, not just any empty state") but worth naming explicitly so it doesn't read as an oversight.
- **Type divergence across clients:** desktop display/UI = Poppins/Inter; mobile PWA still asserts in Instrument Serif 22px; native untouched. Converge or keep as a form-factor exception.
- **Primary action colour differs by client:** desktop primary = ink; mobile PWA light `--action` and native `--action` are Handling/electric blue for filled buttons.
- **Token naming drift:** desktop `--belagt`/`--vagran`/`--papper` vs mobile `--grounded`/`--refusal`/`--paper` vs native TS object — same identity, three vocabularies.
- **Native Avbrott** `#E5484D` vs desktop/PWA `#A82F22` (different reds for “error”).
- **Native/PWA dark handling blues** `#2E6BFF` / `#7EA2FF` vs desktop paper Handling `#1A4FD0`.
- **`site.css` header comment** still describes a “dark application shell”; product chrome is paper — comment lag, not necessarily live dark UI.
- **Amber filled `.ui-btn--warning`** uses Vägran as a solid CTA fill (report flow) — a deliberate, visible exception to “amber = no proof”.
- **Legacy radius scale** (`--radius-2xl`/`--radius-3xl`) coexists with `--r-control`/`--r-card`; migrate surfaces opportunistically, new work uses the new tokens.
- Identity source HTML not in repo — values are transcribed into CSS with long comments; cannot cross-check against original here. And since 2026-08-08 the desktop no longer follows its serif layer at all.
